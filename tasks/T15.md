## Goal
Max: "extend the pane to have more lines per description so I can read what each task is doing better, same thing for the activity, I would prefer no cutting the phrases and using a scroll." The pane should show full task descriptions and full Activity entries, wrapped across lines, and rely on the Pane's own scroll for anything taller than the visible area — not manually truncate/omit content to fit.

## Inputs
- `plugins/coordinator/hooks/register.tsx` — the `ui.render` Pane hook (~line 317+, same one T1 touched)
- `plugins/coordinator/hooks/board.ts` — `detailLine`, `cut`, `short` helpers
- Confirmed from the bundled plugin-authoring types (`claude-code.d.ts`, `Pane.scroll: SiteScroll`): "The body's window over the tree: engine-owned, moved by the person's keys while the pane is focused." `SiteScroll.bodyRows` is "how many rows of the tree the window may show at once... whatever the tree's own height" — i.e. the engine already scrolls a tree taller than the pane natively. The current code doesn't lean on this: it computes `height`/`fixed`/`rest` from `e.props.scroll?.bodyRows` and uses them to decide how many Activity lines to show (`doneRows`, `recent = rest >= 3 ? activity(list, Math.min(8, rest - 2)) : []`) and whether to show the per-task detail line at all (`detail`), purely to avoid overflowing a view that was never actually height-limited to begin with.
- `Text`'s `wrap` prop (claude-code.d.ts ~line 1657-1663, ~2500): default is `'wrap'` (continues on rows under the gutter); the current code explicitly overrides to `wrap="truncate-end"` on the task row, the detail line, wide-mode Summary/Last message/Next cells, agent description lines, and Activity entries — all candidates to switch back to default wrap instead of truncating.

## Done when
- The per-task detail line (narrow mode) and, in wide mode, the Summary/Last message/Next cells no longer call `cut()` on their text or force `wrap="truncate-end"` — they wrap across lines instead, and show the full `short()`-selected clause (keep `short()`'s plain-words clause-picking — that's the IF-style content shaping Max already approved in T12 — just drop the *additional* width-based `cut()` layered on top of it for display).
- The per-task detail line always renders (not gated behind a height-driven `detail` boolean computed to avoid overflow) — in wide mode too, if there's more to say than the column cells show; use judgement on whether wide mode still needs a separate detail line once its cells wrap, or whether wrapped cells are enough. Keep the ID/P/Status/Agent fixed-width columns as they are (short bounded labels, not prose — no change needed there).
- Activity isn't capped by remaining pane height (`Math.min(8, rest - 2)`) or cut mid-phrase — show a generous, simply-bounded window (e.g. the task's existing `KEEP = 8` per-task Progress cap is a separate, reasonable limit; the pane's Activity *feed* cap should stop being `rest`-driven). Each entry wraps instead of being `cut()`.
- Don't remove the `height`/`scroll` read entirely — keep using `e.props.scroll` for whatever the engine still needs from the hook (if anything), but stop using it to decide what content to omit.
- `coordinator.test.tsx`'s pane tests (pane-70, pane-120, "a short pane drops activity...") get updated to assert the new wrapped/unabridged output — read them first, they currently assert specific cut/padded strings and row counts that this change intentionally breaks.
- `claude plugin test` and `claude plugin validate` pass.

## Plan
1. Read `coordinator.test.tsx`'s three pane tests fully before touching render code, so you know exactly what shape they currently assert and can write fixtures whose text is realistic (reasonably short Progress lines, same as production) rather than relying on cutting to keep test output short.
2. In `register.tsx`'s `ui.render` Pane hook: drop the `cut()` calls and `wrap="truncate-end"` overrides on description/summary/message/next/activity text (listed above); keep them on the fixed-width label columns (ID/P/Status/Agent) where cutting a short bounded label is still reasonable.
3. Remove the height-driven suppression (`doneRows`, the `Math.min(8, rest - 2)` activity cap, the `detail` boolean's dependency on `fixed + open.length * ... > height`) — replace with simple, content-driven limits that aren't about fitting a viewport (e.g. always show the detail line; cap Activity at a flat reasonable number like 15-20, or don't cap it at all and let it scroll).
4. Re-run `claude plugin test plugins/coordinator` and `claude plugin validate plugins/coordinator`; fix fixtures/assertions to match the new (correct) behavior, not the old cut behavior.
5. Don't touch `markdown()` (the `/coordinator-board` text reply) — Markdown has no scroll concept of its own and wasn't part of this complaint.
6. Risk: this is a real behavior change to a pane Max uses constantly across projects — don't over-engineer a new layout, just stop fighting the engine's native scroll. If something is genuinely ambiguous (e.g. whether wide mode still wants a separate detail line under wrapped cells), make the simplest reasonable call and say so in Progress rather than guessing silently.
